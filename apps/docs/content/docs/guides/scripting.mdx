# Scripting macup

macup is built to run unattended. Five commands emit structured JSON, exit
codes are stable at the coarse level, and the interactive UI steps aside when
stdout or stdin is not a terminal. See [Verbosity](/docs/guides/verbosity) for
the output modes.

## JSON output

Five commands take `--json`: the cross-plugin `outdated` and `doctor` commands,
and the per-plugin `list`, `install` and `update` subcommands. No other command
emits JSON.

```bash
# Cross-plugin outdated report as JSON
macup outdated --json

# Tracked packages for one plugin as JSON
macup brew list --json

# Install tracked brew packages and emit the end-of-run report as JSON
macup brew install --json

# Upgrade outdated brew packages and emit the end-of-run report as JSON
macup brew update --json
```

With `--json`, `outdated` skips the pill header and the spinner, so nothing
leaks onto stdout before the payload.

`macup outdated --json` emits one object:

```json
{
  "totalOutdated": 3,
  "plugins": [
    {
      "pluginId": "brew",
      "displayName": "Homebrew",
      "available": true,
      "outdated": []
    }
  ]
}
```

`outdated` queries every registered plugin in parallel and isolates per-plugin
failures: a missing binary yields `available: false` with a `reason` instead of
aborting the report. The composite `all` plugin is excluded so packages are not
double-counted. See [Checking what is outdated](/docs/guides/checking-outdated)
for the rendered, human-readable view.

`<plugin> list --json` emits a `PackageStatus[]` array. By default it lists
tracked packages from your applist. Pass `--all` for every installed package,
and `--only-outdated` to keep only outdated entries.

```bash
# JSON of every installed brew package, not just tracked ones
macup brew list --json --all

# Outdated tracked brew packages only
macup brew list --json --only-outdated
```

## Parsing with jq

```bash
# Total outdated count
macup outdated --json | jq '.totalOutdated'

# Plugin ids that have outdated packages
macup outdated --json | jq -r '.plugins[] | select(.outdated | length > 0) | .pluginId'

# Names of outdated tracked brew packages
macup brew list --json --only-outdated | jq -r '.[].ref.name'
```

`<plugin> update --json` emits the end-of-run report: one entry per package the
run attempted, its outcome (`updated` or `failed`, with the backend's message as
`detail` on a failure), and a `summary` of counts. Every outdated package in
scope is attempted even when one fails, and the exit code is `1` iff at least
one package `failed`. Progress lines and notices go to stderr, so a piped stdout
holds only the document. `--dry-run` prints what would run, and no report.

```json
{
  "mode": "update",
  "plugins": [{ "pluginId": "brew", "status": "ran" }],
  "packages": [
    { "pluginId": "brew", "ref": { "kind": "formula", "name": "jq" }, "outcome": "updated" },
    {
      "pluginId": "brew",
      "ref": { "kind": "formula", "name": "fd" },
      "outcome": "failed",
      "detail": "Error: fd: no bottle available"
    }
  ],
  "summary": { "updated": 1, "failed": 1, "unavailable": 0 }
}
```

```bash
# Names of the packages that failed to update
macup brew update --json | jq -r '.packages[] | select(.outcome == "failed") | .ref.name'
```

`macup all update --json` emits the same document across every backend. Each
backend gets a line in `plugins`: `ran`, `unavailable` with the reason (the
backend is not on this machine), or `failed` with the reason (the backend
errored out before it could name a package, so there is no entry to count).
Every backend and every package is attempted even when one fails, and the exit
code is `1` iff a package `failed` or a backend `failed`. An unavailable
backend never forces a non-zero exit on its own. A backend listed in
`skip.all` is not run and does not appear.

```bash
# Backends that errored out, with the reason
macup all update --json | jq -r '.plugins[] | select(.status == "failed") | "\(.pluginId): \(.reason)"'
```

`<plugin> install --json` emits the same shape for an install. Each package's
outcome is `installed` (this run put it on the machine), `already-present` (it
was there before the run started, as the backend's own listing showed) or
`failed`, with the backend's message as `detail`. Every package in scope is
attempted even when one fails, and the exit code is `1` iff at least one
package `failed`. An already-present package is not a failure. With no package
named and nothing tracked, the report is empty and the exit code `0`.
`--dry-run` prints what would run, and no report.

```json
{
  "mode": "install",
  "plugins": [{ "pluginId": "brew", "status": "ran" }],
  "packages": [
    { "pluginId": "brew", "ref": { "kind": "formula", "name": "jq" }, "outcome": "installed" },
    { "pluginId": "brew", "ref": { "kind": "formula", "name": "ripgrep" }, "outcome": "already-present" },
    {
      "pluginId": "brew",
      "ref": { "kind": "formula", "name": "fd" },
      "outcome": "failed",
      "detail": "Error: fd: no bottle available"
    }
  ],
  "summary": { "installed": 1, "already-present": 1, "failed": 1, "unavailable": 0 }
}
```

```bash
# Names of the packages this run actually put on the machine
macup brew install --json | jq -r '.packages[] | select(.outcome == "installed") | .ref.name'
```

Flag spellings are exact: `--json`, `--all`, `--only-outdated` (hyphenated, not
`--onlyOutdated`).

## Exit codes

Codes are stable at the coarse level: `0` success, `1` any failure, `130`
interrupted. The [exit codes reference](/docs/reference/exit-codes) is the
canonical list.

On SIGINT, macup cancels in-flight subprocesses, then exits `130`.

A failing subprocess does **not** propagate its own exit code. The runner
throws a generic error whose message includes the subprocess code, and macup
exits `1`. Do not read the subprocess's exit status from macup's.

## Non-TTY behavior

There is no single non-interactive switch. Code paths check different streams,
so redirecting one changes behavior differently from redirecting another.

- Wizard (no-arg run) checks `stdin`. When stdin is not a TTY, macup prints
  the Apple logo plus a one-line hint
  (`macup — N plugin(s). Run with --help or a command.`) and returns. The
  interactive picker runs only when stdin is a TTY.
- `outdated` spinner checks `stdout`. Piped, the report still prints, just
  without the spinner.
- `all` confirmation checks `stdout`. Piped, `macup all update` and
  `macup all install` proceed without the `Continue?` prompt.
- Color is auto-disabled when stdout is not a TTY or when `NO_COLOR` is set.
  Piped output is uncolored without a flag.

## Keeping stdout clean

`--debug` suppresses the bar and routes the full shell-call trace to stderr, so
stdout stays JSON-only:

```bash
# Full trace to stderr, JSON on stdout
macup --debug outdated --json
```

Preview commands without running them with `--dry-run` (see
[Safe updates](/docs/guides/safe-updates)):

```bash
# Print the commands that would run, without executing
macup brew update --dry-run
```

## Logging a run to disk

`--log <path>` appends a record for every subprocess macup runs: what it ran,
the exit code, how long it took, and the output. Nothing on the terminal
changes, so it composes with everything above.

```bash
macup --log ~/macup.log all update
```

Set `MACUP_LOG` instead when passing the flag every time is impractical, in a
launchd or cron job say. The flag wins when both are set.

Each line is one JSON object (ADR 0045), so multi-line output stays on a single
line and the file is safe to append to from more than one run at once:

```bash
# Every command that failed, most recent last
jq -r 'select(.exitCode != 0) | "\(.ts) \(.cmd) \(.args | join(" ")) -> \(.exitCode)"' ~/macup.log

# The slowest ten commands
jq -s 'sort_by(-.durationMs) | .[:10] | .[] | "\(.durationMs)ms \(.cmd)"' -r ~/macup.log
```

The file is appended to, never truncated, so a scheduled run builds a history
rather than replacing one.

<Callout type="warn">
  The log contains whole subprocess output, so treat it as sensitive. macup
  keeps it `0600`, tightening an existing log that is looser, and masks
  credential-shaped arguments such as `--token`, `--auth-token`, and passwords
  in URLs. It does not attempt to redact the output itself, since
  there is no way to do that without risking either missing a secret or
  mangling the log. Skim it before attaching it to a bug report.
</Callout>

A log path that cannot be written is reported once and the run carries on: a
broken log should not cost you the update.
