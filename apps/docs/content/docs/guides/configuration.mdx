# Configuration

macup tracks your packages in a YAML file:

```yaml
# ~/.config/macup/applist.yaml
brew:
  formulas:
    - git
    - jq
  casks:
    - firefox
npm:
  - typescript
appstore:
  - Xcode

pins:
  npm:
    typescript: "5.3.3"

skip:
  brew:
    - legacy-dep
```

See the [config schema reference](/docs/reference/config-schema) for every key
and its type.

## Starting from what you have

`macup init` scans the machine and writes an applist from what is already
installed, which beats typing it out:

```bash
macup init --dry-run
macup init
```

It merges rather than replaces, so running it again on an existing applist adds
only what is new and leaves pins, skip lists, and comments intact. A populated
applist prompts first; under a pipe it refuses rather than rewriting a config
unattended, and `--force` is how a script says yes in advance (ADR 0046).

Note `macup init <shell>` is a different command. That one emits shell
integration code to eval from your rc file, for example
`eval "$(macup init zsh)"`.

## Resolution order

1. `--applist <path>` (this run only)
2. `$MACUP_APPLIST`
3. `$MACUP_CONFIG` (the spelling that predates `--applist`)
4. `$MACOS_UPDATETOOL_CONFIG` (legacy, emits a deprecation warning)
5. `$XDG_CONFIG_HOME/macup/applist.yaml`
6. `~/.config/macup/applist.yaml`
7. `~/.config/macos-updatetool/applist.yaml` (legacy, auto-migration prompt on first mutation)

## More than one applist

Keeping work and personal packages apart takes one flag:

```bash
macup --applist ~/lists/work.yaml brew track ripgrep
macup --applist ~/lists/work.yaml all update
```

`~` expands and a relative path resolves against the working directory. Set
`MACUP_APPLIST` instead when passing the flag every time is impractical, in a
launchd or cron job say. The flag wins when both are set.

An applist you name this way has to exist. macup creates the default applist on
first write, but a named path that isn't there is far more likely a typo than a
new list, so it stops and shows you the absolute path it looked for. Create the
file first (`touch ~/lists/work.yaml`) to start an empty one.

## Backups

A timestamped backup is written before every config mutation (`track`,
`untrack`, `pin`, `skip`). If nothing changed, no backup is written. Manage them
with `macup cleanup` and `macup restore`.

Backups are scoped to the applist they came from: `work.yaml` snapshots as
`work_track_<timestamp>.yaml`, so `restore` and `cleanup` under one applist
never touch another's, even when both live in the same directory.
